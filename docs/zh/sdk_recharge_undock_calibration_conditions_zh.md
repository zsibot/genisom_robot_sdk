# 回充、退桩与基站标定使用条件和故障说明

## 1. 文档目的

本文面向现场使用、交付和售后人员，说明机器人执行回充、退桩、基站标定前必须满足的条件，以及不同异常现象通常对应的原因和处理方法。

本文按照当前软件逻辑整理。文中不展开软件内部通信接口和节点名称，只描述客户可以观察和处理的外部条件。

## 2. 三项任务共同依赖的条件

回充、退桩和基站标定都依赖视觉、基站通信、机器人运动和标定数据四部分同时正常。任意一部分不满足，任务都可能无法开始，或者在执行中途停止。

### 2.1 现场和设备条件

- 机器人电源正常，未处于急停、跌倒、严重硬件故障或禁止运动状态。
- 机器人底盘、腿部、充电触点和基站机械结构没有明显变形、松动或卡滞。
- 基站放置稳定，机器人能够从当前方向接近或离开基站；基站不能在任务执行过程中移动。
- 基站前方和退桩方向没有人员、宠物、杂物、墙角或其他会影响运动的障碍物。
- 摄像头镜面清洁，没有灰尘、水雾、遮挡、保护膜残留或明显反光。
- 现场光照足够且稳定。过暗、逆光、频闪或补光灯被遮挡，都可能导致识别不稳定。

### 2.2 基站识别条件

- 相机视野中必须能够看到目标基站的识别标志，并且标志足够大、清晰、没有被遮挡。
- 同一时刻只能有一个与当前任务匹配的目标识别标志出现在有效视野中。
- 不能把多个相同目标标志同时放在相机视野内。即使这些标志属于不同基站，只要编号相同，也会造成目标位置无法唯一确定。
- 不同编号的其他标志通常不会被当作目标，但现场仍建议只让目标基站进入视野，避免误判和遮挡。
- 机器人和基站之间不能有中途经过的反光物、玻璃、镜面或快速移动物体。

这里的“只能有一个二维码”更准确地说，是“相机有效视野中只能有一个匹配当前配置的目标基站识别标志”。并非环境中所有二维码都必须清除，但实际交付时应尽量保证目标基站是视野内唯一的基站标志。

### 2.3 基站通信条件

- 机器人已经选择并配对正确的基站，不能连接到另一台基站或残留旧基站连接。
- 基站与机器人之间的无线连接稳定，基站状态能够持续更新。
- 基站有电，能够响应开灯、停止充电、开始充电等操作。
- 基站没有持续性的硬件、通信、温度或充电故障。
- 更换基站、修改基站地址或更换基站主板后，应确认机器人使用的是该基站对应的配置和标定数据。

回充和基站标定要求基站已配对且连接正常。退桩以“基站已连接”为正常路径，但当前版本额外支持一种直退路径：系统收到新鲜且明确的“基站已断连”状态后，会跳过基站控制，直接进入站立和后退。

### 2.4 标定数据和运动条件

- 相机内参、相机安装位置参数和基站位置标定数据必须存在、可读取且内容有效。
- 标定数据必须与当前机器人、当前摄像头和当前基站匹配。把另一台机器人或另一台基站的参数直接复制过来，可能导致机器人持续偏移或撞桩。
- 回充开始时，机器人应处于能够识别基站的站立姿态；不能一开始就趴倒、严重偏航或被障碍物卡住。
- 运动对准模块需要持续获得新鲜的基站位姿。视觉一旦停止更新，机器人会停止输出有效运动，任务可能等待超时或失败。
- 接触对准不是“已经碰到基站”的同义词。机器人还必须经过精对准，并由基站确认实际接触。

## 3. 回充任务

### 3.1 正常执行条件

回充能够正常完成，至少应同时满足以下条件：

1. 目标基站已配对、已连接，且状态稳定。
2. 基站识别标志清晰可见，视野中没有重复的目标标志。
3. 当前机器人使用的相机和基站标定数据正确。
4. 机器人处于可站立、可移动状态，基站前方没有障碍物。
5. 机器人与基站之间的初始距离和角度在视觉对准能够覆盖的范围内。
6. 基站触点、充电电源和充电状态反馈正常。
7. 电池状态能够正常更新，不能处于电池数据丢失或明显异常状态。

### 3.2 正常流程

回充大致按照以下顺序执行：

1. 检查标定数据、视觉能力和运动对准能力。
2. 根据配置打开基站补光灯，机器人调整到站立姿态。
3. 打开基站识别，识别目标标志并计算机器人与基站的相对位置。
4. 机器人依次完成粗对准、精对准和接触对准。
5. 机器人执行接近基站的末端动作，并等待实体触点接触确认。
6. 向基站请求开始充电，并等待基站真正进入充电状态。
7. 停止不再需要的视觉跟踪和补光灯，进入充电监控。
8. 充电期间持续监控基站状态和电池状态；满电后保持在基站上，等待用户发起退桩或其他合法状态切换。

命令被基站接受，不等于已经开始充电。只有“充电状态已经生效”并持续更新，才算回充成功。

SDK 可通过 `OnTaskStateData()` 的 `phase` 辅助展示上述进度：准备阶段对应
`recharge_preparing`，对桩和进桩对应 `recharge_docking`，充电监控对应
`recharge_charging`，满电保持对应 `recharge_completed`。`phase` 可能为空或出现
后续新增值，不能代替 `task_status` 判断任务结果。

### 3.3 回充异常现象和原因

| 现象 | 常见原因 | 处理建议 |
| --- | --- | --- |
| 一开始就提示视觉或标定不可用 | 相机标定文件缺失、不可读或内容损坏；相机参数与当前设备不匹配 | 检查相机和基站标定数据，确认文件来自当前机器人；必要时重新标定 |
| 机器人完全找不到基站 | 标志被遮挡、光照不足、相机脏污、图像没有更新、机器人朝向偏离过大 | 清洁镜头、改善光照、移除遮挡物，让机器人正对目标基站后重试 |
| 偶尔能看到基站，但任务仍失败 | 识别标志过小、画面模糊、反光、目标时有时无，或位姿更新不连续 | 增大基站在画面中的占比，固定光照和基站，避免人员从前方经过 |
| 提示目标不唯一或位置不稳定 | 相机同时看到了两个相同目标标志，或多个基站使用了相同目标编号 | 只保留目标基站进入视野；检查现场是否有重复标志，确认目标编号规划正确 |
| 机器人能看到基站，但不断左右或前后修正，不能靠近 | 基站位置标定不准确、基站被移动、地面不平、机器人初始姿态偏差过大 | 重新固定基站并重新标定；将机器人放到更正的初始位置后重试 |
| 进入接触阶段前后不动 | 视觉位姿过期、对准误差仍太大、目标标志暂时丢失，或运动控制处于保护状态 | 保证连续识别，清除障碍，确认机器人未急停；重新从正对基站的位置开始 |
| 已经接近基站，但始终没有接触确认 | 充电触点高度或横向位置不合适、触点脏污、基站倾斜或机器人姿态异常 | 检查并清洁触点，检查基站水平和固定情况，确认机器人末端姿态正确 |
| 已经接触，但没有开始充电 | 基站连接断开、基站未配对当前机器人、充电电源异常、触点接触不良或基站内部报错 | 先确认基站连接和状态，再检查电源、触点和基站故障提示；不要连续快速重复下发充电操作 |
| 开始充电后很快又失败 | 基站连接或状态反馈中断、基站掉电、充电故障，或电池状态停止更新 | 检查基站供电和无线连接，确认充电状态持续存在；必要时退出后重新回充 |
| 任务显示已满电但机器人仍在基站 | 这是正常保持行为，满电后不会自动离开基站 | 需要离开基站时，单独发起退桩任务 |

## 4. 退桩任务

### 4.1 正常执行条件

退桩能够正常完成，至少应同时满足以下条件：

1. 机器人确实位于目标基站上，且当前没有正在执行其他运动任务。
2. 正常退桩时，基站连接稳定，能够完成补光灯控制，并确认停止充电后的状态变化；若要走断连直退，系统必须能收到新鲜且明确的“基站已断连”状态，状态缺失或过期不算断连。
3. 目标基站识别标志可见且唯一；相机视野中不能出现两个相同的目标标志。
4. 退桩方向和周围区域畅通，机器人后退路径上没有障碍物。
5. 相机标定和基站位置标定正确，机器人能够持续看到基站并计算相对位姿。
6. 机器人能够从充电姿态恢复到站立姿态，腿部、底盘和运动控制正常。
7. 如产品配置启用了退桩防碰撞检测，相关距离传感器必须正常工作且数据连续。

### 4.2 正常流程

退桩大致按照以下顺序执行：

1. 检查标定数据和视觉能力。
2. 启动基站识别，确认当前目标基站可持续识别。
3. 判断基站最新连接状态，并按以下两条路径执行：
   - 基站明确已断连：跳过补光灯、停止充电和停充后的静置等待，直接进入站立和后退。
   - 基站已连接、连接状态未知或状态过期：打开补光灯，请求停止充电并确认已停止，静置后再站立。
4. 机器人恢复到站立姿态。
5. 机器人根据基站位姿向后退出，持续修正方向和横向偏差。
6. 到达预设安全退桩位置后停止运动，关闭本次识别和补光资源。

正常连接路径的成功判断是“基站通信步骤已完成、充电已停止、机器人已站立、已到达退桩位置并停止运动”。断连直退路径不再等待补光灯或停止充电结果，直接以“已确认断连、机器人已站立、已到达退桩位置并停止运动”作为流程条件。

SDK 可通过 `OnTaskStateData()` 的 `phase` 辅助展示上述进度：准备阶段对应
`undock_preparing`，退桩运动对应 `undock_undocking`，完成阶段对应
`undock_completed`。最终是否成功仍以 `task_status == SUCCESS` 为准，不能要求
`phase` 必须非空。

### 4.3 基站断连时的直退行为

当前版本支持“基站明确断连后直接退桩”。这里的“断连”有严格条件：系统必须刚刚收到有效的基站状态，并且其中明确显示基站已断连；没有基站状态、状态太旧，或者仍显示已连接，都不会进入直退路径。

断连直退的实际顺序如下：

1. 仍会完成标定数据检查、基站视觉识别和退桩能力检查。
2. 确认基站为明确断连后，跳过开补光灯、停止充电及其结果确认，不再执行连接路径中的停充后静置等待。
3. 机器人直接站立，再根据持续的视觉定位后退到安全退桩位置。
4. 任务结束时，系统仍会尽力发送停止充电和关闭补光灯的收尾通知，但不会等待基站响应，也不会阻塞本次直退结果。

因此，断连直退是“跳过主流程中需要确认结果的基站交互”，不是“跳过所有前置检查后立刻盲退”。视觉识别、站立确认、障碍物保护和退桩位置收敛仍然必须满足。

如果基站实际上已经断开，但系统没有收到新鲜的断连状态，就会按保守策略尝试原有基站交互；这时交互失败可能导致任务失败。现场应先等待基站状态刷新，或恢复连接后按正常路径退桩。

### 4.4 退桩异常现象和原因

| 现象 | 常见原因 | 处理建议 |
| --- | --- | --- |
| 任务开始即失败 | 标定数据缺失或不可读；机器人状态不允许运动 | 检查设备状态和标定数据，清除急停或故障后重试 |
| 提示没有识别到基站标志 | 机器人被基站遮挡、镜头过近、光线不足、标志被触点或结构挡住 | 确认相机能看到目标标志，改善光照，检查镜头和基站安装位置 |
| 周围有多个基站或多个相同标志时失败 | 目标不唯一，系统无法判断应该从哪一个基站退桩 | 将非目标基站移出视野或遮挡其标志；确保不同基站的目标编号规划不重复 |
| 明明能看到标志，仍提示识别失败 | 识别结果没有连续更新、画面模糊、目标标志太小或有反光；也可能是系统版本中的识别结果传递异常 | 先固定机器人和光照并重新执行；若重复出现“看得到但系统不认可”，记录现场视频和任务时间交给售后 |
| 基站已断连后，机器人直接站立并后退 | 系统收到新鲜且明确的基站断连状态，进入断连直退路径 | 这是当前版本的预期行为；确认退桩方向畅通、视觉识别持续有效 |
| 基站实际已断连，但任务仍尝试开灯或停止充电后失败 | 断连状态没有及时更新、状态过期，或系统仍认为基站已连接 | 等待状态刷新；必要时恢复基站连接后重新发起完整退桩 |
| 一直停在基站上，充电没有停止 | 基站连接断开、基站拒绝停止充电、基站状态没有更新或基站仍报告故障 | 检查基站连接、电源和故障提示；确认充电状态已变为停止后再继续操作 |
| 停止充电后无法站立 | 腿部或底盘故障、外部物体压住机器人、机器人不在预期充电姿态 | 清理周围空间，确认机器人机械状态和安全状态，必要时人工维护后重试 |
| 退桩过程中突然停住 | 视觉位姿丢失、检测到障碍、传感器数据中断、基站被移动或机器人偏离路径 | 先不要推动机器人；清除人员和障碍物，恢复传感器和视觉条件后重试 |
| 一直提示有障碍，无法完成退桩 | 退桩区域确实有障碍，或防碰撞传感器被遮挡、污染、数据异常 | 清空退桩区域，清洁传感器；确认无误后重新执行 |
| 机器人已经离开基站但任务没有完成 | 未到达预设退桩位置、位姿误差没有稳定收敛，或识别结果中途丢失 | 让机器人重新回到可识别、无遮挡的位置执行；不要在运动过程中强行搬动机器人 |

### 4.5 关于“只能有一个二维码”的现场要求

退桩最容易受到目标不唯一影响。客户现场应按以下规则布置：

- 相机能看到的范围内，只保留当前基站的一个目标识别标志。
- 不要在相邻基站上使用相同的目标编号。
- 不要让镜面、屏幕、打印件或其他反光物产生类似目标的图像。
- 如果现场有多个基站，退桩前应确认机器人连接的是正确基站，并让其他基站离开相机视野。

因此，“周围只能有一个基站”是最稳妥的现场要求；从算法规则上说，真正必须唯一的是相机视野中的目标识别标志和目标基站。

## 5. 基站标定任务

### 5.1 正常执行条件

基站标定能够正常完成，至少应同时满足以下条件：

1. 基站已经通电，并与当前机器人配对、连接正常。
2. 系统能够识别出当前基站的有效身份。更换基站后不能继续沿用未确认的旧基站身份。
3. 相机内参和相机安装位置参数已经准备好；基站标定不能替代相机本身的基础标定。
4. 机器人和基站均保持静止，标定期间不要推动机器人、调整相机或移动基站。
5. 相机在短时间内能够连续、清晰地看到唯一目标标志。
6. 目标标志没有遮挡、反光、严重倾斜或运动模糊。
7. 存储空间和配置文件权限正常，系统能够写入新的基站标定结果。

### 5.2 正常流程

基站标定大致按照以下顺序执行：

1. 启动视觉识别。
2. 在规定时间内连续获取多帧稳定的基站位姿。当前逻辑要求短时间内连续得到 5 帧有效结果。
3. 触发手动基站标定，使用当前识别到的目标计算基站相对位置。
4. 将结果保存到与当前基站身份对应的标定数据中，并加载到后续定位流程。
5. 检查文件是否能够读取，并建议立即执行一次回充或退桩验证实际效果。

标定成功的必要条件不是“看到过一次二维码”，而是“唯一目标、连续稳定识别、基站身份有效、计算结果合理并成功保存”。

### 5.3 标定异常现象和原因

| 现象 | 常见原因 | 处理建议 |
| --- | --- | --- |
| 标定任务无法开始 | 基站未连接、基站身份无效、相机基础标定缺失或已有标定任务未结束 | 先确认基站配对连接和相机基础标定，再重新发起标定 |
| 5 秒左右仍未通过稳定识别 | 目标标志看不见、图像模糊、光照不稳定、机器人或基站在移动 | 固定双方，清洁镜头并改善光照，保证目标标志完整进入视野 |
| 提示目标重复或位姿不稳定 | 同一画面出现多个相同目标标志，或者周围有相似图案和反光 | 只保留一个目标标志，移除重复标志和反光物后重新标定 |
| 标定过程中持续识别但最终失败 | 识别位姿质量差、相机安装参数错误、目标距离或角度不合适 | 调整机器人和基站的相对位置，核对相机安装参数，重新执行 |
| 标定命令被接受但最终没有成功 | 接受命令只表示开始处理，后续可能因目标丢失、计算失败或写文件失败而结束 | 查看最终任务结果，不要只依据“开始”提示判断成功 |
| 提示文件写入或读取失败 | 存储空间不足、文件权限异常、文件系统只读或原文件损坏 | 检查存储和文件系统，保留原文件备份后再由维护人员处理 |
| 标定显示成功，但回充方向明显错误 | 标定结果对应了另一台基站、基站后来被移动、当前任务未使用刚标定的数据 | 确认当前连接基站与标定对象一致，固定基站后重新标定并做回充验证 |

### 5.4 多基站场景的要求

同一台机器人可以面对不同基站，但每个基站都应有自己的标定结果，并且标定结果必须和该基站的身份绑定。现场应做到：

- 标定时只让当前基站的目标标志进入相机有效视野。
- 标定前确认当前连接的就是要标定的基站。
- 更换基站后，先确认系统识别到了新基站，再检查或重新生成该基站的标定结果。
- 不要用 A 基站的标定结果验证 B 基站，也不要只复制一个通用文件覆盖所有基站。
